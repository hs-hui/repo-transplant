# Security

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/hs-hui/repo-transplant/security/advisories/new). Please do not open a public issue for a security problem.

## Threat model

Repo Transplant reads repositories written by strangers and hands their content to an AI agent that can change your code. It assumes the source repository is hostile.

### Attacks it is built to stop

| Threat                                                                   | Defense                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Code running during fetch through hooks, filters, submodules or symlinks | Fetch uses `init` and `fetch --depth=1`, not `clone`. Hooks are disabled, symlinks are checked out as plain files, submodules and LFS are skipped, and the `.git` directory is deleted.                                                                                                                                                                 |
| Malicious URLs                                                           | Only https or ssh to allowed hosts. Refs are validated. No credentials in URLs. Git's `ext` and `file` transports are off. The one exception is `allow_local`, which reads a repository on this machine through the `file` transport. Network paths are refused even then.                                                                                                                                                                                                                              |
| Path traversal                                                           | Paths are validated, then resolved with `realpath` and checked for containment.                                                                                                                                                                                                                                                                         |
| Prompt injection in docs or comments                                     | Files are returned inside labeled untrusted markers, and the scanner flags text addressed to agents, fake role tags and hidden Unicode. The skill forbids acting on any of it.                                                                                                                                                                          |
| Skipping the process                                                     | The stage machine runs in the server. Approval binds to a hash of the spec, plan and base commit. Audits and evidence bind to a hash of the files read directly from disk, so git's index flags, ignore rules, filters and diff drivers hide nothing. Tests run in a copy built from those same files, so code outside the hash cannot affect a result. |
| Unreviewed scope growth                                                  | The audit compares every changed file, including ignored ones outside install and build output, and every added line with the approved plan. Binary files and nested repositories are flagged.                                                                                                                                                          |
| Supply chain                                                             | npm, pnpm, yarn and bun installs must use `--ignore-scripts`, unless the plan gives `install_scripts_reason`, which you see at approval. New packages, version changes and install scripts must be in the plan. `package_inspect` catches invented package names.                                                                                                                                                                                       |
| Secret theft by accident                                                 | Commands get an allowlisted environment and a temporary home directory, so tools do not pick up credentials by default. Plans cannot set variables that load code, such as `NODE_OPTIONS`.                                                                                                                                                              |
| Damage to shared databases                                               | Commands cannot name a non-local connection string, and the tool never applies migrations to shared environments.                                                                                                                                                                                                                                       |
| Fabricated results                                                       | Test evidence must name text the command really printed, for the current tree, from a test run. A run with no tests, one where every test was skipped, or one that rewrites tracked files does not pass. A skipped test is not evidence, a manual criterion stays open for a person, and a visual one needs a real image.                                                                                                                                                                                 |
| Escape through git | Commands run in a copy with no `.git`. Every git call has hooks and the file monitor off and keeps secrets out of its environment, including calls on a path the agent chose. A repository whose own config runs a filter program is refused, unless it is exactly the standard Git LFS filter. Replacing the worktree's `.git` entry raises a finding that cannot be accepted. |
| Work hidden from the review | `transplant_commit` builds the commit in a throwaway index from the bytes the review read, and returns a hash to merge, so the worktree's index, filters and hooks take no part. Commits on the branch, a changed index, refs that shadow the branch, and `refs/replace` entries raise findings that cannot be accepted. |
| Accepting more than was shown | An accepted finding covers one version of one file or folder, so a later edit needs a new acceptance. The dialog shows the rule, the file and the reason. A person's no is recorded, and the agent's word cannot follow it. |
| A flagged file kept out of the trace | The scan of the whole repository is kept for the session. A file it flags that the plan neither traces nor cites needs `out_of_scope_reason`, which the approval summary and the report show. Cited files are matched to the repository listing and rescanned, so a different spelling of a path cannot skip the gate, and a citation the scan cannot read is refused. Copying from a left-out file is a high finding, counted across all changed files. Files the feature imports stay gated even when so many others import them that they are mapped rather than copied. |
| Files that resist scanning | A selected or cited file is read in full whatever its size, UTF-16 is decoded, and a selected file that is binary, other than an image, font or similar asset, blocks approval. The audit decodes files the same way, and a lone carriage return in a change is a high finding. |
| Redirected builds | TOML manifests and `composer.json` are compared after parsing, so a spelling the tool accepts cannot hide a source or a `[patch]` table, and a manifest that does not parse is a high finding. A package that keeps its version but gains a git, path or registry source is a high finding, even if approved. Files that steer a build, such as `.cargo/config.toml`, `build.rs`, `go.work`, `Directory.Build.props` and `nuget.config`, need `sensitive_paths_reason`, and so does citing an agent's settings or a binary from the source. |
| Hostile text in tool output                                              | File reads use a random end marker and show hidden characters as `[U+202E]`. Excerpts are sanitized.                                                                                                                                                                                                                                                    |

### What it does not stop

- **Verification runs real code on your machine by default.** A reduced environment is not a sandbox. The code can read your files, including `~/.ssh`, reach the network, and change session state. Read the code before running it, or use `verification.docker_image`. The Docker mode is tested against a live daemon: the network is off except during install, and timed-out containers are stopped.
- **The scanner is pattern-based.** A careful attacker can write malicious logic that looks ordinary, or phrase an injection in a new way.
- **A compromised agent can lie.** On clients that show no MCP elicitation dialog, the server records what the agent says you said when you approve a plan. Overrides and accepted high findings refuse to run this way unless `RT_ALLOW_ATTESTED=1` is set, because in testing an agent claimed an acceptance nobody gave. It cannot tell a real approval from an invented one, though the report labels these as agent-recorded. Headless clients count as having no dialog, because they cancel every request within milliseconds. Set `RT_REQUIRE_DIALOG=1` to refuse those. Watch the session.
- **A left-out reason is written by the agent.** The server shows it and cannot judge it. On a client with no dialog, nothing proves you read it, so a compromised agent can leave a flagged file out on a false reason.
- **A trace can still miss a file.** Kotlin files that declare several classes, Rust `#[path]` modules and two classes with one fully qualified name are known gaps. The whole-repository scan still flags what it can read in them. A missed file with nothing to flag goes unnoticed.
- **The whole-repository scan has limits of its own.** Over-limit files and binary data under a text extension are noted, not read, unless the plan selects them. Tracked `node_modules` is skipped, so a plan cannot cite it. The license pass reads SPDX tags in source, test and style files, outside vendored directories.
- **A hard kill or a crash skips cleanup.** A normal shutdown stops running commands and containers. A forced kill can leave them running until they finish.
- **Ignored install output is outside the review.** Ignored files under `node_modules`, and under `dist` or `build` beside a manifest, are not audited. They are also absent from the copy where commands run, and git would not commit them.
- **Test evidence is matched as text.** A misled agent could quote printed text that is not a test name. The `transplant-reviewer` agent and your own review exist for this. A run with every test skipped is also read from the runner's output, so a runner the server does not know, or one called through a script such as `make test`, can still pass that way. Plans must run `go test` with `-v`, because plain `go test` prints the same line for a skipped package and a passing one.
- **The local-database check reads text.** It catches mistakes in connection settings, not a command built to hide its destination.
- **Git settings are checked, not neutralized.** Config, hooks and attributes that change during a session raise a high finding that cannot be accepted. They still apply to your own later git commands, so use the commit `transplant_commit` returns rather than committing by hand.
- **An agent with a shell outside the worktree is outside this model.** It can do whatever your account can. Other branches that move during a session are reported, not prevented.
- **Session files are local and unsigned.** They protect against mistakes and a misled agent, not against code or a person with write access to your disk.

Treat the report as a statement of what was checked, not as proof that the code is safe. A person should review the diff before it merges.
